# mechanical/ — printed parts as code (Sprint 5, S8)

> **NO DIMENSION IN THIS DIRECTORY IS VERIFIED. Nothing has been measured with
> calipers, nothing has been printed, nothing has been test-fitted.** Every value
> is a nominal figure from a manufacturer drawing (named next to it) or a guess
> (marked "guess"). Measure your own parts before printing.

Parametric OpenSCAD files for the optional printed parts listed in
`docs/HARDWARE.md`. All parts fix to the Rover 5 deck with **glue, double-sided
tape or zip ties**; none of them assumes holes drilled in the deck.

### HC-SR04 layout (3 front at −25° / 0° / +25°, 1 rear)
Print the same file four times:
- front-left: `yaw_deg = 25` (preview `out/hcsr04_holder_yaw25.png`);
- front-centre: `yaw_deg = 0`;
- front-right: `yaw_deg = -25` (mirror of +25);
- rear: `yaw_deg = 0`.

Glue each base with its straight front edge square to the deck edge; the
sensor then points at the set angle. Alternatively print four `yaw_deg = 0`
holders and glue the outer two turned 25° by eye. The cans sit in the face
holes; a zip tie through the two face slots holds the board. Which sign is
"left" depends on how you look at the robot: check against `docs/ROBOT_SOFTWARE.md`
sensor names before gluing.

## Build (STL + PNG)
```
bash mechanical/build.sh                # Git Bash / Linux
powershell -File mechanical\build.ps1   # PowerShell
```
Both run `render_all.sh` inside the official `openscad/openscad:2021.01`
image (override with `OPENSCAD_IMAGE`). Each part is exported to
`out/<part>.stl`, then the STL is rendered to `out/<part>.png` (800 × 600)
under a hand-started Xvfb (the image's `xvfb-run` hangs in Docker). Echo lines
(e.g. panel top height, strap length) are printed. A full run takes ~15 s.

Change a value without editing the file: `openscad -D panel_t=9 -o x.stl display_bracket.scad`.

**Outputs in git:** the PNG previews in `out/` are committed (small, ~100 kB
total). STL files are git-ignored (~2 MB) and regenerated by the build.

## Print settings (suggestions, not tested)
- PETG preferred (the robot sits near warm electronics and in sunlight); PLA is fine for a first fit test.
- 0.2 mm layers, 3 perimeters, 25–30 % infill (40 % for the pan cradle and display stands).
- Orientation: as modelled (flat face on the bed). The display stands and the HC-SR04 face print upright without supports; the pan cradle prints open-side up.
- Print **one** HC-SR04 holder and the Pi plate first as fit tests — they are quick.

## What to measure first (in this order)
1. **Waveshare panel:** thickness at the edge (`panel_t`), where HDMI / USB connectors exit (stands must not cover them → `stand_inset`), bottom bezel width (`bezel_clear`).
2. **MG996R:** body length/width, height from the bottom to the flange underside (`flange_z` is a pure guess), flange hole spacing, round horn diameter and hole circle.
3. **Webcam:** the foot/clip width and depth (`cam_clip_w`, `cam_clip_d`); whether it has a 1/4"-20 thread.
4. **HC-SR04 (the borrowed ones):** can diameter and centre spacing (clones differ), how far the header pins stick out.
5. **Battery holder:** outer length/width/height once chosen (`holder_x/y/h`).
6. **Pi 5:** hole spacing only as a check (the drawing is reliable, but confirm).
7. **Printer fit:** print a test peg/hole and set `fit_clearance` in `common.scad`.

After measuring, edit the variable, keep the `// VERIFY WITH CALIPERS` tag
but change the source to "measured YYYY-MM-DD".

## What is not verified
Everything: all dimensions, the 15° display tilt, the stand/strap strength,
heights above the deck (panel top ≈ 111 mm by the current guesses), clearance
between parts on the deck, the servo shaft offset, and whether the webcam clamp
fits the actual webcam. Nothing was printed.
